# 存档与迁移 · schema 5

## 默认和启用

默认关闭云存档；未发布工程即使配置开关也只在本地试玩。不要把 Stop 后丢失的本地档误认为云保存失败。

真实验证请先备份旧档、复制独立测试体验，再按平台规则配置 DataStore 访问并设 `C.EnableCloudSave = true`。**Studio 访问在线 DataStore 时可能接触实际数据，不要拿生产玩家档做故障注入。** 单看配置开关不足以证明保存已成功。

## 兼容约定

- DataStore 名：`Dustbound2D_Profile_v1`；键：`u_<UserId>`。
- 外层 envelope：`data`、180 秒会话锁 `lock`、`lastWriteId`。
- schema 5：保留四种材料、科技、图鉴、局数与完成波次；增加教程完成标记、runSerial/settledSerial、研究目标、配装/预设、设置。
- schema 4 字段会清洗后补默认值。早期 armor/drill/power 迁移仍走原规则，不双重叠加。
- 首通标记与资源在同一个档案快照写入，不在 UpdateAsync 回调里追加奖励。
- 根 envelope 非表、缺少表形式 data、更新于 schema 5 的档案会被拦截，避免按当前结构重写。该检查不是所有数据损坏的自动修复器。

## 状态和行为

| 状态 | 行为 |
|---|---|
| local | 本次 Play 有效；Stop / 离开不保存。 |
| read_error | UI 可显示，开始被挡住；重试读取或明确选择 guest。不会拿默认空档覆盖云档。 |
| guest | 新的临时试玩档，不写、不覆盖、不合并原云档；离开丢失。 |
| cloud / saving | 已持锁 / 正在写；结果页和设置显示状态。 |
| save_error | 内存保留当前进度和稳定待写快照，允许重试；断线前未成功保存仍可能丢失。 |
| lock_lost | 停止写入并冻结游戏；通过 Roblox 菜单退出后重进。未保存修改可能丢失。 |

保存触发：开始、元数据变更、结算、45 秒自动保存、离开和关服。保存函数 `flush` 先写完上次待重试快照，再写新的修改，最后才释放锁。写入 ID/快照保持稳定，重试不是重复加奖励。获取锁的响应若丢失，可用原令牌重试认领。

## 必须在真实服务补测

1. 新档 → 教学首通 → 研究 → 换装 → 改音量/目标/预设 → 等待“上次云保存成功” → 离开重进。
2. schema 4 备份样例迁移；资源/科技未减少、没有重复叠加，新字段默认正确。
3. 读取被拒、限流、保存失败恢复、同一账号快速重连、锁过期、服务器关闭。
4. 明确访客后玩一局，确认没有把访客材料写进原云档。
5. 保存失败后再修改设置，恢复后重进确认新旧修改均保留。
6. 不把 `saving` 当成功；不要用“设为 false 再 true”合并访客数据。

离线故障注入覆盖了关键分支，但 mock 不模拟 Roblox 的真实调度、预算、重试、并发服务器或关服时限。**不保证永久服务故障下的数据持久化；没有战斗中途断线续局。**
